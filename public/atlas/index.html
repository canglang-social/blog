§1 · the vocabulary

Five primitives, one anatomy

A prompt is stored text — raw material. A command is the thin loader that deploys it as fixed steps. A command usually wears a role — a standing identity with judgment and boundaries. A workflow is the recurring loop that composes all three; a project is the built thing that comes out the other end.

PrimitiveAnswersNatureInvoked by
RoleWHO acts, by what judgmenta standing identity"act as X" / a command wearing it
CommandWHAT procedure runsa repeatable task/command

Workflowthe recurring loop + purposea processruns via its commands/roles

§2 · where judgment lives

Five judgment-roles

Roles appear where judgment concentrates; commands suffice where the task is procedural. That is why the system is mostly workflows + commands with exactly five roles — and why /scout or /tailor never needed a persona. The Chief audits the other four from outside — chief, not auditor of its own doing — and, since 2026-08-04, can chair them as a council: seats spawned blind, one cross-examination round, dissent preserved, Felix alone deciding.

Chief of Staff

Owns the inventory and the meta-calls: keep, merge, automate, retire; which tool for a role; the decision-layer anatomy. Advises first, never touches; on Felix's confirmation, executes via worktree branch + draft PR — or better, delegates to the owning workflow with a brief. Also the ground-strategy seat across the decision layers.

Owns vault conventions, drift cleanup, and the mobile capture pipeline (Siri → [[inbox/mobile]] → [[inbox]]). Conventions, not content — producer loops own what they append; the vault is a sink.

Owns blog voice and style, the draft pipeline, /writing curation, and the language policy: one language per published page, always a native-English refine pass. Critiques and refines — never ghostwrites.

Owns public image and charisma (positioning, image pillars, per-platform bios), social-media strategy, and the outside-in surface audit — a recruiter's eyes on how it all comes across. Drafts frames; Felix writes the words. Routes blog-copy fixes to the Editor.

§3 · how the seats work together

Seven collaboration modes

Named 2026-08-04 — the mode is part of a workflow's shape, so it lives in workflows.md next to the loop diagrams. Ask "which mode is this?" before "which tool?". Five run, one is partial, one is deliberately unbuilt. Felix alone decides, in every mode.

#ModeStatusShapeOperational home
1Delegaterunningbrief → owner executes in its own repoTODO.md item via draft PR (carrier rule below)
2Auditrunningoutside fact-check; never edits owned files/audit + the mechanical checker
3Adjudicaterunningchief settles two seats' overlapping claimsrow overlaps: entries / boundary rules — first: learning-loop vs wiki-management, 2026-07-05; unnamed until 2026-08-04
4Deliberaterunningseats spawned blind, one cross-exam, dissent preserved/council — first convening 2026-08-04 (own-vs-access)
5Pipelinerunningone-way data edges; collaboration by artifact, no shared sessionthe canonical edge table (§7)
6Broadcastpartialfact-change propagation to dependent surfaces/next due-soon scan (dates only)
7Consultnot builtone seat, one question, no full councilthe owning seat's own ritual instead (Treasurer memo, /crossroads)
Delegation carrier rule (unified 2026-08-04): a delegated brief lands as a TODO.md item in the owner's repo, delivered by draft PR; non-project life items keep the journal. GitHub issues retire as an internal delegation channel — the carrier is a file, because every reading surface (/next, the reviews, the audit) reads files, never the issue API. Every brief carries five fields: FROM · ASK · OWNER · DONE-WHEN · REPORT-BACK.

Broadcast stays partial: beyond dates, propagation is manual (the career rename sweep); a third manual sweep is the trigger to design a check. Consult stays unbuilt: single-seat questions route to the owning seat's ritual; a second council convened for a one-seat question is the trigger to reconsider.
