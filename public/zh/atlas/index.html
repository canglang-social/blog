§1 · 词汇表

五个原语，一副解剖图

提示词（prompt）是存储的文本——原材料。命令（command）是把它按固定步骤部署出去的薄加载器。命令通常会扮演一个角色（role）——一个带判断力与边界的常设身份。工作流（workflow）是把三者组合起来的循环；项目（project）则是从另一端产出的成品。

原语回答什么本质由谁调用
角色「谁」来行动、依据什么判断常设身份"act as X" / 由命令扮演
命令运行「什么」程序可重复的任务/command
提示词存储的指令文本资产（原材料）由加载器/命令部署
工作流循环本身 + 它的目的过程经由其命令/角色运行
项目造出来的东西制品（产出）你直接使用
§2 · 判断力所在

五个判断型角色

角色出现在判断力汇聚的地方；任务是程序性的地方，命令就够了。这就是为什么系统大体是「工作流 + 命令」、角色恰好只有五个——也是为什么 /scout 或 /tailor 从来不需要一个专属人设。幕僚长从外部审计其余四个——对自己的作为，它是幕僚长，而非审计员——并且自 2026-08-04 起，还能以主席身份把它们召集成一个议会：各席位盲写立场、一轮交叉质询、异议被保留，决定只由 Felix 一人做出。

幕僚长

拥有清单和各项元决策：保留、合并、自动化、退役；某个角色该配哪种工具；决策层的解剖结构。先建议、绝不直接动手；经 Felix 确认后，通过 worktree 分支 + 草稿 PR 执行——或者更好：带着任务简报，委派给拥有该事务的工作流。同时也是横跨各决策层的底层战略（ground-strategy）席位。

驻地：ai-chief-of-staff · chief-of-staff.md

图书馆员

拥有知识库的约定、漂移清理，以及移动端采集流水线（Siri → [[inbox/mobile]] → [[inbox]]）。管约定，不管内容——生产循环拥有各自追加的内容；知识库是汇聚点。

驻地：知识库本身 · [[Wiki/Librarian]] + [[Wiki/Conventions]]

编辑

拥有博客的声音与风格、草稿流水线、/writing 的策展，以及语言政策：每个发布页面只用一种语言，全部经过母语级英文润色。批评与润色——绝不代笔。

驻地：blog · editor.md（2026-07-07 就位）

品牌教练

拥有公开形象与魅力（定位、形象支柱、各平台简介）、社交媒体策略，以及由外向内的界面审计——用一双招聘官的眼睛看这一切给人的观感。教练搭框架；文字由 Felix 来写。博客文案的修改转交编辑。

驻地：暂驻 ai-chief-of-staff · brand-coach.md（2026-07-07）

司库

拥有金钱事实文件、门槛备忘录（每笔 ¥5,000 及以上的支出，以及每个重大决策），还有每月复盘中「当下『富有』意味着什么」这一追问——有日期的答案只追加、不覆盖。范围是生活而非工作：不做日常记账，不追求超额收益——把收入当作杠杆来用，那是 career-strategy 的事。这里的一切永不公开。

驻地：money · treasurer.md（2026-07-12；循环自 2026-08-02 起运行）

§3 · 各席位如何协作

七种协作模式

2026-08-04 命名——模式是一个工作流形状的一部分，所以它住在 workflows.md 里，紧挨着各循环图。先问「这是哪种模式？」，再问「用哪个工具？」。五种在运行，一种部分实现，一种刻意未建。每种模式下，决定都只由 Felix 一人做出。

#模式状态形状运行驻地
1委派运行中简报 → 拥有者在自己的仓库里执行TODO.md 条目，经草稿 PR 送达（载体规则见下）
2审计运行中从外部核查事实；绝不编辑对方拥有的文件/audit + 机械检查器
3裁断运行中幕僚长裁定两个席位互相重叠的主张行级重叠：条目 / 边界规则——首例：learning-loop vs wiki-management，2026-07-05；直到 2026-08-04 才得名
4审议运行中席位盲启动，一轮交叉质询，异议被保留/council——首次召集 2026-08-04（拥有 vs 使用权）
5流水线运行中单向数据边；以制品协作，不共享会话权威边表（§7）
6广播部分实现事实变更向依赖它的各界面传播/next 的到期扫描（仅限日期）
7咨询未建一个席位、一个问题，不开全体议会改走拥有席位自己的仪式（司库备忘录、/crossroads）
委派载体规则（2026-08-04 统一）：委派的简报落为拥有者仓库里的一条 TODO.md 条目，由草稿 PR 送达；与项目无关的生活事项仍走日志。GitHub issue 作为内部委派渠道退役——载体是文件，因为每个读取界面（/next、各级回顾、审计）读的都是文件，从不读 issue API。每份简报都带五个字段：FROM · ASK · OWNER · DONE-WHEN · REPORT-BACK。

广播维持部分实现：日期之外的传播是手动的（career 改名清扫）；出现第三次手动清扫，即触发设计一项检查。咨询维持未建：单席位的问题路由到拥有席位自己的仪式；若第二次为单席位问题召集议会，即触发重新考虑。
